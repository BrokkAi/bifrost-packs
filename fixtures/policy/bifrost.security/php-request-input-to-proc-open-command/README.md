# PHP request value to proc_open command fixture

Qualifies `bifrost.security.php.request-input-to-proc-open-command` for the
version- and OS-independent part of BrokkAi/bifrost-packs#311 (CVE-2024-1874,
[GHSA-pc52-254m-w9w7](https://github.com/php/php-src/security/advisories/GHSA-pc52-254m-w9w7)).
The source is a `$_GET` read. The sink is the command argument of the
`proc_open` declaration in the native `bifrost.php-builtin` pack. A string
command runs through the shell everywhere. An array command is not escaped for
`cmd.exe` on Windows PHP before 8.1.28, 8.2.18 and 8.3.5, which is the CVE. The
rule reports both forms on every runtime and OS, because the engine has no
Windows target or PHP runtime evidence to narrow it.

Each case directory is its own workspace with `.php-version` 8.3.0, the policy,
and a copy of the reviewed `bifrost.php-process-summaries` 0.1.0
(`semantic-packs/php/process/`) in `.bifrost/semantic-models`.

## The php-builtin pack matters

The `proc_open` declaration only binds as complete with a `bifrost.php-builtin`
pack generated by `bifrost-semantic-pack` 0.15.2 or later (bifrost-dev#9337),
which certifies the callable family. `packs/v0.14.0` still ships the shard made
by the 0.15.1 producer (`e8e6ad9c…`, 0 certified records), so with that release
every case is inconclusive and the near miss can't be clean. This change moves
the producer pin in `native-generation.json` to 0.15.3. The first packs release
built with it carries the certified shard.

## Cases

| Case | Code | Expected |
| --- | --- | --- |
| `positive-array-batch` | `proc_open(['convert.bat', $name, 'out.png'], …)` | 1 definite (line 8), `proven_by_summary` |
| `positive-string-concat` | `proc_open('convert ' . $name . ' out.png', …)` | 1 definite (line 7), `proven_by_summary` |
| `positive-string-whole` | `proc_open($command, [], $pipes, '/srv/tools')` | 1 definite (line 7), `proven_by_summary` |
| `positive-import-alias` | `use function proc_open as start_process;` then `start_process($command, …)` | 1 definite (line 9), `proven_by_summary` |
| `near-miss-constant-array` | the request value is read, the command array is constant | 0, `proven_by_summary` |
| `unknown-escapeshellarg` | `escapeshellarg($_GET['name'])` concatenated | 0, `inconclusive`: `escapeshellarg` has no reviewed summary |
| `unknown-request-comparison` | the request value only selects whether a constant command runs | 0, `inconclusive`: the comparison leaves procedure semantics unknown on 0.15.3 |

The fixtures avoid `$_GET['x'] ?? ''` followed by `.`, which is inconclusive on
Bifrost 0.15.3 (bifrost-dev#12563).

## Known limits

- Only `$_GET` is a source.
- The Windows-only, runtime-version part of the CVE is not checked, so an
  array-command finding on Linux or a fixed runtime is reported as well.
- `exec`, `system`, `shell_exec`, `passthru` and `popen` are not sinks.
- Reads from the `$pipes` resources are not modeled (see
  `semantic-packs/php/process/README.md`).
