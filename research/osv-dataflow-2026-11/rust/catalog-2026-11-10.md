## #371: why the pack is unchanged

The obligation comes from bifrost-dev#10879, which is newer than the pinned
release. To discharge it, the pack must prove that dropping the result runs
nothing the network policies care about. None of the destruction contracts
that exist can say that truthfully:

- `value_semantics.drop_glue: "inert"` (schema 22) means the type has no
  `Drop` impl and no field's drop glue runs user code. A socket closes its OS
  handle in `OwnedFd`/`OwnedSocket`'s `Drop`, so `inert` would be false. The
  error side, `std::io::Error`, can own a boxed custom error, so it isn't
  inert either.
- Schema 31 `value_semantics.drop_effects` has only
  `memory_or_refcount_release`, and closing a handle is neither. Its scoped
  admission is not live on bifrost-dev master, and 0.15.1 cannot load
  schema 31.

A `return_type` for `connect` on its own would not discharge the obligation,
because the payload drops stay unproven. It also can't be qualified on the
pin: on 0.15.1, `call-effects` for both `TcpStream::connect(addr);` and a
returned `TcpStream::connect(addr)` is already `bifrost.network_io`,
`exhaustive`, `immediate`, `definite` with the current pack. Changing the
embedded pack would add an unqualified schema change and no checkable
behavior, so it waits for #11326 and a pinned release that has #10879.

## Promotion criteria

#371 can land when bifrost-dev#11326 adds a reviewed destruction effect for
releasing an OS handle and a release with #10879 and that contract is the
pin. The pack then needs the `connect` return type, the socket facts, and a
fixture showing that a discarded `connect` keeps exhaustive network-effect
coverage while a near miss with a user type that has its own `Drop` stays
open.
